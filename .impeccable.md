# Impeccable — project design context

## Design Context

### Users
Creative professionals and ambitious hobbyists ("Cursor for creative" audience) making images/video/design assets. They are NOT ComfyUI node-graph experts — the product hides the engine and guides them. Mental state in the studios: exploring, wants results fast, easily intimidated by empty expert-looking forms. Cost-aware: paid actions must show price before click.

### Brand Personality
Precise, calm, quietly confident. "Linear-grade" dark UI: glassy cards, hairline borders, white-opacity neutrals. Guardrails over knobs — the tool encodes best practices so users can't hold it wrong.

### Aesthetic Direction
Dark theme throughout (studio/creative-tool context). White accent as the primary; emerald exclusively for run/generate actions; amber for warnings/character accents. NEVER violet/purple. Type idioms: `text-[13px]` headings, `text-[11px]` labels (uppercase tracking-wide for section headers at white/50), `text-[10px]-[11px]` helper text at white/30-40. Existing shared primitives (StudioSection, StudioModalShell) are the vocabulary — extend, don't reinvent.

### Design Principles
1. Guardrails should be visible: when the tool encodes a best practice, say it in one line where the decision happens.
2. Empty states teach the flow (numbered next actions), then get out of the way — guidance disappears once the user starts.
3. Money is explicit: every paid button carries its ~$ label.
4. One accent per meaning: emerald=run, amber=warn, red=error, white=structure.
5. Match the file's existing idiom before inventing a new one.
